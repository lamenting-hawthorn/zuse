---
title: Shared plugins
description: Use the same tools and accounts across local, cloud, and different coding agents.
---

Zuse connects to [Executor](https://executor.sh), a shared service for MCP tools, OpenAPI APIs, and GraphQL APIs. Connect an account in Executor once and use its tools from supported agents in your local and cloud workspaces.

## Connect

1. Open **Settings → Plugins** in the environment where your agent runs.
2. Enter your Executor service root or organization MCP URL (for example, `https://executor.sh/your-organization/mcp`) and a **personal API key** from that service.
3. Choose **Connect and enable**. Use **Manage tools and accounts** to add integrations, connect accounts, and configure approvals in Executor.
4. Refresh the catalog. Optionally select a toolkit to restrict the available connections and actions.
5. Start a new chat and ask your agent to use the connected tools.

To share tools with another local or cloud environment, connect that environment to the same Executor instance and account. This shares service connections; Zuse does not automatically copy your desktop access key to other machines. Cloud workspaces need a reachable HTTPS service URL, not your laptop's localhost address.

## Multiple accounts and agents

Executor can hold multiple account connections for the same service. Their names appear under the integration in Zuse. Use distinct names such as “Work GitHub” and “Personal GitHub”, and configure toolkits to control which accounts an agent may use.

Shared plugins are wired to Claude Code, Codex, Cursor, Gemini, Grok, Kiro, OpenCode CLI, and supervised ACP adapters. ACP tools must support MCP; Zuse bridges stdio when HTTP is unavailable. This does not install native Codex or Claude hooks, commands, or skills into other agents. Zuse UI extensions remain a separate feature.

## Data and permissions

Executor stores your service connections and applies its tool policies. Zuse stores the Executor access key using the selected runtime's credential store. Agent processes receive a temporary runtime-local proxy token, not the durable Executor key. Tool inputs and results pass through the chosen Executor deployment and the agent's normal conversation flow.

Use Executor's account and toolkit settings to restrict tools and require approvals. The catalog lists integrations visible to your account; a selected toolkit may allow only some of them. Verify approval behavior with your chosen agent before using write actions.

## Disable or disconnect

**Disable** blocks further Executor requests from this runtime and preserves its connection settings. **Disconnect** removes this runtime's saved connection. Neither action deletes service accounts in Executor or changes other environments. Actions already sent to a service may finish.

Start a new chat after enabling, reconnecting, or changing toolkits. Existing conversation history remains available. When Executor is unavailable, Zuse shows an error and keeps your saved connection so you can retry.
